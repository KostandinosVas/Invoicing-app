# ADR-0004: Κύκλος ζωής παραστατικού ως state machine

**Κατάσταση:** Αποδεκτό
**Ημερομηνία:** 2026-09-02

## Context

Το παραστατικό περνά από διακριτές καταστάσεις: προσχέδιο, εκδοθέν, υπό
διαβίβαση, αποδεκτό ή απορριφθέν από την ΑΑΔΕ, ακυρωμένο. Οι μεταβάσεις δεν
είναι ελεύθερες — ένα εκδοθέν παραστατικό δεν επιστρέφει σε προσχέδιο, και ένα
ακυρωμένο δεν πάει πουθενά.

Η επικοινωνία με την ΑΑΔΕ είναι ασύγχρονη και μπορεί να αποτύχει. Χρειάζεται
τρόπος να διακρίνεται ένα παραστατικό που **στάλθηκε και περιμένει** από ένα
που **δεν στάλθηκε ποτέ**.

## Options

**Α. Πεδίο `status` ως string.** Οποιοδήποτε σημείο του κώδικα μπορεί να γράψει
οτιδήποτε. Τυπογραφικό λάθος (`'draftt'`) περνά σιωπηλά και εμφανίζεται σε
production.

**Β. Boolean flags** (`is_issued`, `is_submitted`, `is_cancelled`). Επιτρέπει
αδύνατους συνδυασμούς: ακυρωμένο και μη εκδοθέν ταυτόχρονα.

**Γ. Πακέτο state machine** (π.χ. `spatie/laravel-model-states`). Λύνει το
πρόβλημα αλλά προσθέτει εξάρτηση και abstraction για λογική ~40 γραμμών.

**Δ. PHP enum με ρητό πίνακα μεταβάσεων.**

## Decision

**Δ.** `App\Enums\InvoiceStatus` ως backed enum, με τις επιτρεπόμενες μεταβάσεις
ως μέθοδο του ίδιου του enum.

draft ──► issued ──► submitting ──┬──► submitted ──► cancelled
│
└──► rejected ──► submitting

Λεπτομέρειες που έχουν σημασία:

- **Το `submitting` υπάρχει ως ξεχωριστή κατάσταση.** Χωρίς αυτό, ένα
  παραστατικό που κόλλησε στην ουρά είναι δυσδιάκριτο από ένα που δεν στάλθηκε
  ποτέ — και ο χρήστης δεν έχει τρόπο να δει ότι κάτι είναι σε εξέλιξη.
- **Το `rejected` επιστρέφει στο `submitting`.** Η απόρριψη δεν είναι τελική:
  διορθώνεις και ξαναστέλνεις.
- **Το `cancelled` είναι τερματικό**, και αυτό προκύπτει από τον πίνακα
  μεταβάσεων (`isFinal()` επιστρέφει true όταν δεν υπάρχουν έξοδοι) αντί να
  δηλώνεται χωριστά.
- **`match` αντί για `switch`** — είναι exhaustive: νέα κατάσταση που δεν
  χειρίζεται πουθενά πετάει `UnhandledMatchError` αντί να περνά σιωπηλά.
- **Μη επιτρεπτή μετάβαση πετάει `DomainException`**, όχι `false`. Είναι
  παραβίαση κανόνα του domain, όχι τεχνικό σφάλμα — και ο τύπος του exception
  το κάνει διακριτό στο error handling.

## Consequences

**Κερδίζουμε:** αδύνατες καταστάσεις δεν αναπαρίστανται· ο interpreter και το
PHPStan εγγυώνται εγκυρότητα· ο πίνακας μεταβάσεων είναι ένα σημείο αλήθειας
και διαβάζεται ως τεκμηρίωση.

**Πληρώνουμε:**

- Ο πίνακας μεταβάσεων πρέπει να ενημερώνεται χειροκίνητα σε κάθε νέα
  κατάσταση. Το `match` το επιβάλλει με σφάλμα εκτέλεσης.
- Η επιβολή είναι στον κώδικα, όχι στη βάση: η στήλη είναι `varchar` και ένα
  raw SQL update θα την παρέκαμπτε. Δεν προστέθηκε CHECK constraint γιατί θα
  απαιτούσε migration σε κάθε αλλαγή του enum.
- Δεν καταγράφεται ιστορικό μεταβάσεων. Αν χρειαστεί («πότε εκδόθηκε, πότε
  διαβιβάστηκε»), θα απαιτηθεί ξεχωριστός πίνακας.
