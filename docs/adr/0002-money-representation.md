# ADR-0002: Χρήμα σε ακέραια λεπτά με Money value object

**Κατάσταση:** Αποδεκτό
**Ημερομηνία:** 2026-09-01

## Context

Το σύστημα εκδίδει φορολογικά παραστατικά. Κάθε ποσό είναι νομικά δεσμευτικό
και διαβιβάζεται στην ΑΑΔΕ. Λάθος ενός λεπτού σε τιμολόγιο δεν είναι
στρογγυλοποίηση — είναι λάθος έγγραφο.

Οι πράξεις που εκτελούνται: τιμή × ποσότητα, ποσοστό ΦΠΑ επί της καθαρής αξίας,
άθροισμα γραμμών. Οι συντελεστές ΦΠΑ στην Ελλάδα είναι 24%, 13%, 6% και 0%,
και μπορούν να συνυπάρχουν σε **διαφορετικές γραμμές του ίδιου παραστατικού**.

Η αναπαράσταση δεκαδικών σε floating point είναι εγγενώς ανακριβής:
`0.1 + 0.2 !== 0.3`. Σε συσσωρευτικές πράξεις το σφάλμα μεγαλώνει.

## Options

**Α. Float / double.** Απορρίπτεται εξ ορισμού για χρήμα.

**Β. Decimal στη βάση (`numeric(12,2)`).** Η Postgres το χειρίζεται σωστά, αλλά
η PHP το επιστρέφει ως string και κάθε πράξη απαιτεί ρητή μετατροπή. Ένα
ξεχασμένο cast σε float και το σφάλμα επιστρέφει σιωπηλά.

**Γ. Ακέραια λεπτά (`bigint`) σκέτα.** Ασφαλής αποθήκευση, αλλά η αριθμητική
μένει σκορπισμένη στον κώδικα: κάθε σημείο που υπολογίζει ΦΠΑ αποφασίζει μόνο
του πώς στρογγυλοποιεί.

**Δ. Ακέραια λεπτά + Money value object.** Η αποθήκευση του Γ, με τις πράξεις
συγκεντρωμένες πίσω από ρητό API.

## Decision

**Δ.** Κάθε νομισματικό πεδίο αποθηκεύεται ως `bigint` σε λεπτά. Οι πράξεις
γίνονται μέσω `App\ValueObjects\Money`, wrapper πάνω από το `brick/money`.

Κανόνες που επιβάλλει το value object:

- **Immutable.** Κάθε πράξη επιστρέφει νέο `Money`.
- **Ιδιωτικός constructor**, δημιουργία μόνο μέσω `fromCents()`. Ένα σημείο
  εισόδου, καμία αμφιβολία για τη μονάδα.
- **Ρητή στρατηγική στρογγυλοποίησης** (`HalfUp`) σε κάθε πολλαπλασιασμό.
- **Ο πολλαπλασιαστής δέχεται `string`, όχι `float`** — το `0.24` ως float
  είναι ήδη ανακριβές πριν ξεκινήσει η πράξη.

Ο συντελεστής ΦΠΑ αποθηκεύεται ως **ακέραιο ποσοστό** (24, όχι 0.24) και
ανήκει στη **γραμμή**, όχι στο παραστατικό.

Το API δέχεται και επιστρέφει λεπτά. Η μετατροπή σε ευρώ γίνεται μόνο στο UI.

Τα σύνολα **αποθηκεύονται** αντί να υπολογίζονται κατά την ανάγνωση: το
παραστατικό είναι append-only (βλ. ADR-0003), οπότε αν αύριο αλλάξει ο τρόπος
στρογγυλοποίησης, τα παλιά πρέπει να εξακολουθούν να δείχνουν ό,τι έδειχναν.

## Consequences

**Κερδίζουμε:** καμία απώλεια ακρίβειας· η στρογγυλοποίηση είναι απόφαση, όχι
παρενέργεια· ο τύπος αποτρέπει την πρόσθεση διαφορετικών νομισμάτων.

**Πληρώνουμε:**

- Απαιτείται το `bcmath` extension. Δηλώνεται στο Dockerfile και στο CI.
- Κάθε μετατροπή λεπτά↔ευρώ πρέπει να γίνεται συνειδητά στο UI.
- Η ποσότητα παραμένει `decimal(12,3)` — δεν είναι χρήμα, και τιμές όπως 2,5
  κιλά είναι υπαρκτές. Η Postgres την επιστρέφει ως string, που περνά
  κατευθείαν στο Money χωρίς ενδιάμεσο float.
- Τα αποθηκευμένα σύνολα μπορούν θεωρητικά να αποκλίνουν από τις γραμμές αν
  κάποιος τις τροποποιήσει παρακάμπτοντας τη λογική. Ο κίνδυνος περιορίζεται
  από το append-only μοντέλο.
